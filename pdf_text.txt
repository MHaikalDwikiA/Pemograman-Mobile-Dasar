2.1 Definisi RESTful API & Mengapa Aplikasi Mobile Membutuhkannya?	
RESTful API (Representational State Transfer Application Programming Interface) adalah 
antarmuka komunikasi data berbasis web yang memanfaatkan protokol standar HTTP/HTTPS 
untuk menjembatani pertukaran informasi antar sistem yang berbeda. Pada aplikasi mobile modern

Alasan Krusial: Tiga alasan fundamental mengapa aplikasi mobile mutlak membutuhkan RESTful 
API:	
1. Kapasitas Memori Ponsel Terbatas: Menyimpan jutaan riwayat nomor resi pengiriman secara 
lokal di HP pengguna akan menghabiskan ruang penyimpanan dan membuat smartphone lambat 
(crash).	
2. Data Bersifat Terpusat, Real-Time, & Multi-User: Paket logistik bergerak dari kurir lapangan ke 
gudang transit hingga ke tangan penerima. Pembaruan lokasi yang di-input kurir di Jakarta harus 
langsung terbaca oleh konsumen di Surabaya secara detik demi detik melalui database terpusat.	
3. Keamanan & Integritas Bisnis: Menyimpan koneksi database fisik (seperti user/password 
MySQL) di dalam berkas APK Android sangat berbahaya karena berkas APK dapat dibongkar 
(reverse engineering) oleh pihak tak bertanggung jawab. API bertindak sebagai dinding pelindung 
yang aman.	
Metode HTTP Utama: Metode HTTP Esensial pada RESTful API:	
• GET: Mengambil data dari server tanpa mengubah kondisi database (contoh: melacak posisi 
nomor resi).	
• POST: Mengirimkan data baru dari aplikasi mobile ke server untuk disimpan (contoh: 
mendaftarkan paket kiriman baru).	
• PUT / PATCH: Memperbarui data yang telah ada di server (contoh: kurir mengubah status 
paket menjadi DELIVERED).	
• DELETE: Menghapus rekaman data tertentu dari server.

2.3 Cara Kerja & Alur Data (Data Flow Architecture) Pemanggilan API	
Proses komunikasi antara aplikasi Android dan server REST API berjalan melalui 6 tahapan 
terstruktur yang melibatkan pembagian Thread kerja:	
1. Langkah 1 (User Action): Pengguna mengetik nomor resi (misal 'EXP-8801') pada form input 
dan menekan tombol 'Lacak'. Aplikasi memvalidasi agar input tidak kosong.	
2. Langkah 2 (State Loading): Aplikasi segera mengaktifkan indikator ProgressBar berputar, 
menyembunyikan Card hasil data lama, dan menonaktifkan tombol Lacak guna mencegah double-
request.	
3. Langkah 3 (Background IO Thread): Menggunakan lifecycleScope.launch(Dispatchers.IO), 
Retrofit mengemas nomor resi menjadi URL HTTP GET: https://[domain]/api/v1/tracking/{resi} 
lalu menembakkannya ke server melalui OkHttp Client.	
4. Langkah 4 (Audit Payload oleh Interceptor): OkHttp Logging Interceptor mencegat paket data di 
Logcat, mencetak URL, Header, dan Body data yang dikirim maupun diterima untuk audit 
pengembang.	
5. Langkah 5 (Server Processing & Deserialisasi Gson): Server Backend mencari data resi dan 
mengembalikan status HTTP (200 OK jika ditemukan, atau 404 Not Found jika tidak ada). Gson 
Converter otomatis mengurai teks mentah JSON menjadi objek Kotlin TrackingResponse.	
6. Langkah 6 (UI State Rendering): Melalui withContext(Dispatchers.Main), antarmuka diperbarui 
secara instan: ProgressBar disembunyikan, tombol diaktifkan kembali, Card informasi paket 
ditampilkan dengan badge status berwarna (Hijau untuk DELIVERED, Kuning untuk 
IN_TRANSIT), atau menampilkan pesan galat merah jika resi tidak terdaftar.

6. TROUBLESHOOTING UMUM & TIPS DEBUGGING	
Jika menemui kendala teknis saat praktikum konsumsi API, periksa daftar solusi cepat berikut:	
• 1. java.lang.SecurityException: Permission denied (missing INTERNET permission): 
Penyebab: Lupa menambahkan <uses-permission 
android:name="android.permission.INTERNET" /> di AndroidManifest.xml. Solusi: Daftarkan 
izin sebelum tag <application>, lakukan Uninstall aplikasi lama di emulator, lalu Run ulang.	
• 2. CLEARTEXT communication to ... not permitted: Penyebab: Android versi 9 ke atas 
(API 28+) memblokir URL HTTP biasa (tanpa SSL). Solusi: Selalu gunakan protokol HTTPS 
pada BASE_URL di ApiClient.kt, atau tambahkan android:usesCleartextTraffic="true" pada tag 
<application> jika server lokal.	
• 3. android.os.NetworkOnMainThreadException: Penyebab: Mengeksekusi fungsi jaringan 
Retrofit langsung di Main Thread. Solusi: Wajib bungkus pemanggilan service di dalam blok 
lifecycleScope.launch(Dispatchers.IO).	
• 4. Expected BEGIN_OBJECT but was BEGIN_ARRAY: Penyebab: Struktur JSON server 
adalah Array ([...]) namun model balikan Retrofit didefinisikan sebagai Objek tunggal ({...}). 
Solusi: Sesuaikan tipe balikan method service menjadi Response<List<NamaModel>> atau 
pastikan endpoint mengembalikan satu objek tunggal.
